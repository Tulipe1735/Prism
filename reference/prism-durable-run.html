刷新重建参考卡

排查“创建成功，但刷新后不一致”时，用这张卡区分 canonical facts、projection cache 与 browser cache。

Canonical hierarchy

四份状态，四种职责

Manifest / immutable

固定 Run ID、创建时间、原始 repair request 与 request artifact 引用。

runs/<runId>/manifest.json

Journal / canonical

逐行保存版本化事件；runId 必须一致，sequence 必须从 1 连续增长。

runs/<runId>/events.jsonl

Artifact / verified bytes

引用包含 SHA-256、byteLength 与 mediaType；读取时重新计算并比较。

artifacts/sha256/<prefix>/<hash>

Snapshot / disposable cache

由 manifest + journal 重建；缺失、无效或过期时可安全改写。

runs/<runId>/snapshot.json
Reload algorithm

loadRun(runId)

  1. 用 runIdSchema 拒绝不安全路径。
  2. 读取并用 runManifestSchema 校验 manifest。
  3. 逐行解析 journal；每一行都必须是合法 RunEvent。
  4. 调用 projectRunEvents，从 null 重建 snapshot。
  5. 读取 request artifact，验证长度与 SHA-256，再解析为 RepairRequest 并与 manifest 中的 request 精确比较。
  6. 读取 snapshot 引用的其余 artifact，并验证长度与 SHA-256。
  7. 比较并修复 snapshot.json cache；若 journal 比缓存曾见证的 lastSequence 更短，则拒绝降级。
  8. 把 manifest、events、snapshot 映射成 versioned dossier。
packages/trajectory-store/src/index.ts → apps/web/lib/server/run-repository.ts
Do not confuse

触发器、缓存与真相

router.push / router.refresh — 触发导航和重新渲染，不保存 Run。

TanStack Query initialData — 接收服务端 dossier，不建立权威事实。

Zustand statusFilter — 临时筛选器，不改变任何 Run event。

snapshot.json — 投影缓存，不得覆盖 journal 的结果。

Manifest + journal + verified artifacts — 刷新恢复的事实基础。

Fail closed

损坏映射

corrupt_manifest

manifest 缺失、JSON/Schema 无效、内部 runId 与目录不匹配，或 request 不再等于 hashed request artifact。

corrupt_event

journal 行无效、事件跳号、Run 不匹配、起始事件错误或终态后仍有事件。

corrupt_artifact

artifact 缺失、不可读、byteLength 不同或 SHA-256 不匹配。

Visible terminal dossier

Repository 将完整性错误显示为 terminal error，不静默加载不可信状态。
