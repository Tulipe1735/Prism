Repair request 信任边界

改 contract 或排查 validation 时，按此顺序定位。

Browser boundary

即时反馈

  1. 构造 draft。
  2. repairRequestSchema.safeParse(draft)。
  3. 失败：显示字段错误，不 fetch。
  4. 成功：POST JSON。
  5. 再校验服务器响应 schema。
apps/web/components/field-desk/repair-composer.tsx
Server boundary

独立信任

  1. Content-Type 必须是 JSON。
  2. body 不得超过 16 KiB。
  3. JSON 必须可解析。
  4. 同一 request schema 必须通过。
  5. workspace 必须匹配服务端配置。
apps/web/app/api/repair-requests/route.ts
Response map

状态码与 contract

200 — validated；明确没有 runId

400 — malformed JSON

413 — body 超限

415 — 非 JSON media type

422 — schema、版本或 workspace 不支持

Change checklist

改 schema 时

  1. 先改一条单测并看到红。
  2. 改 packages/contracts/src/index.ts。
  3. 更新 draft 生产者，不复制校验规则。
  4. 更新 route boundary tests。
  5. 运行 format、lint、typecheck、test、build。
