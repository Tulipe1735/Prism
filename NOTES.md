# Teaching notes

- Teach Prism from real entrypoints, functions, contracts, tests, and observable browser
  behavior before introducing an architectural label.
- Keep each lesson to one concrete win. For durable Runs, first teach why the same Run
  can be rebuilt after refresh; leave append concurrency, runtime DAGs, Pi, and UI-TARS
  for later lessons.
- Use these terms consistently:
  - **Manifest**: immutable identity and original request.
  - **Journal**: ordered canonical Run history.
  - **Snapshot**: rebuildable projection cache.
  - **Artifact**: content-addressed bytes verified against their reference.
- Distinguish course coverage from demonstrated learning. Do not create a learning
  record or claim mastery until the user completes a retrieval task or explains the path
  in their own words.
- Prefer short Chinese explanations, a real test as the executable story, and a compact
  reference card for later review.
