# PROTOTYPE — Prism run workspace

Status: `selected UI prototype — D / Field Desk`

Question:

> Which information hierarchy makes one Visual SWE repair run easiest to
> understand across its DAG, sibling runtimes, evidence, and safety boundary?

The selected prototype lives at `/prototype/prism`.

- D — Field Desk is a feedback-driven A + C fusion with a prominent repair entry,
  recent cases, and a dossier that unfolds beneath the workspace-level home.

## Feedback absorbed

- A made the user entry obvious.
- C made one run legible but felt like entering directly into an existing case.

## Verdict

The human selected D. Prism enters through a workspace-level repair request,
then reveals active fieldwork and progressively deeper run evidence. The
dossier is a second-level run view, not the product's front door.

This is the official UI prototype for implementation planning. It remains
throwaway design code: implementation should preserve the interaction and
information-hierarchy decision, then rewrite it against real contracts and
runtime state instead of promoting this mock-data component unchanged.
