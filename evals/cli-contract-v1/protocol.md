# CLI contract v1: prospective zero-model mechanism study

Date: 2026-10-05 (Asia/Shanghai). Post-hoc mechanism hypotheses, prospective new
execution block; local source freeze, not external preregistration. No model calls,
credentials, remote pages or product bypass flags. This is a deterministic browser
mechanism study, not a model benchmark or an agent-success experiment.

## Questions and treatments

RQ-O: Which requested group bindings are actually recoverable from current Local,
Structural and Relations target fields across section, legend, ARIA group and table-row
DOMs? Measure field exposure, not model reasoning. Keep candidate sets and states fixed.
Hypothesis: scope effects depend on the extractor and DOM; a richer-named scope need not
expose every relation. Supplemental deep ancestors and shared 24-character heading
prefixes test explicit extractor bounds.

RQ-E: Holding the displayed Relations evidence and an initially correct selection fixed,
how does evidence consistency change actual wrong input and valid input refusal? Compare
the production Sessions class with a research-only dependency ablation that returns the
original evidence at the read boundary. Both arms perform the live read, the same
document/identity/state checks, action schema checks, receipts and CDP input. Only
context comparison is neutralized; no production bypass is added. These paired effects
describe program behavior conditional on the frozen controller choice. They do not
measure what an LLM chooses or prove how an LLM reasons.

H-E1: group swaps before read can invalidate a group-goal choice while leaving the
physical node fresh; evidence consistency will prevent some wrong inputs. H-E2: the same
swap need not invalidate an entity-goal choice, so goal-blind consistency can refuse a
still-valid input. Nonessential local-note updates can also cause refusal. H-E3: a swap
after the read can escape both gates; the check is not atomic. H-E4: changes beyond the
displayed relation prefix can escape the gate. A field-coverage failure is not a
controller decision failure. Report negative findings without repair inside the
execution block.

## Enumerated design and units

Four hand-crafted DOM families, two skeletons each, three counterbalanced positions and
entity/group mappings: 24 page states from eight base pages. Every entity visits every
group and position. Each state has an entity goal and a group goal requesting the same
initial control. Every task is run in both gates under six mutations: stable, unrelated
text, swapped group headings, nonessential local note, node replacement, and a swap
immediately after the evidence read. Primary block: 24 × 2 × 6 × 2 = 576 cells.

The post-read swap is a deliberately injected scheduling boundary inside the research
read dependency, not a claim about spontaneous race frequency. The two arms share the
injection point. Scoring uses the app state immediately before input, including this
mutation. Page state is re-created for each cell. Dispatch rotates gate order; execution
is sequential. No extra retries or outcome-driven repetitions. No model/seed/temperature
applies. There is one deterministic cell per condition, not 576 independent tasks.

Supplemental truncation block: four ordinary family skeletons with shared heading
prefixes × two goals × two gates, group swap only = 16 cells. Report separately.
Observation coverage: 24 ordinary states × three scopes = 72 captures; four family
states × two boundary constructions × three scopes = 24 supplemental captures. Transport
check: four ordinary family states × two goals × four mutations (stable, unrelated,
group swap, replacement) = 32 actual short-process production CLI cases. This is
implementation parity evidence, not a third arm or additional task population.

## Oracle and estimands

Initial choice is intentionally privileged: an instrument controller selects the known
correct entity. No aggregate controller grounding rate is a model result. Oracle truth
comes from independent app entity/group state and the click event log, not the tested
context extractor. Assert full visible headings match that state. Record the original
node's connectivity and visibility, current goal correctness, attempted command,
receipt, actual clicks, correct and wrong clicks. Node replacement makes the old
physical input ineligible even if a replacement could satisfy the task; its refusal is
not a false rejection. Entity-goal group changes and nonessential local notes preserve
eligibility.

Primary estimands: within-task paired differences in wrong-click rate and false-refusal
rate, stratified by mutation and goal. Denominators include all enumerated cases and all
recorded errors; report eligible-currently-correct denominators separately. Refusal is
never task success. Input acknowledgement is compared to actual click events. No DONE,
planning, recovery policy, partial-success threshold or strict agent success is
measured.

Use page/family tables and paired differences. No Wilson, McNemar, bootstrap p-value or
mixed-effects inference for this deterministic constructed census. Eight base pages are
the highest defensible cluster; the four families share the generator. A model study
will need independent task sampling and task-cluster uncertainty.

Observation cost is UTF-8 bytes of serialized complete observation and displayed target
fields; no tokenizer, prompt tokens, inference cost or cost reduction claim. Goal and
oracle metadata must not enter the tool observation. Scope is fixed by the instrument,
not adaptive selection.

## Preservation and failure handling

Before final execution, archive explicit method inputs and their hashes, actual Node,
Chrome and Git revision. Save each observation and each result immediately, exclusive
creation; do not overwrite or append an old block. At end verify method hashes and
historical raw/source archive hashes against the initial inventory. Keep errors as
infra/unresolved records, report missing cells, and do not repeat a failed cell
silently. If preflight exposes an instrument bug, fix it, label preflight as
development, freeze the revised method, and start a separate final block. A final source
drift invalidates that block; record it rather than updating its manifest.

## Decision rules and limitations

Tool evidence strengthens the narrow hypothesis that node identity and displayed
relation validity differ, and quantifies conservative refusal under this controller. It
cannot establish that explicit bindings improve LLM grounding, that feedback improves
agent recovery, that CLI is better than MCP, that relations are minimal sufficient, or
that realistic browser tasks improve. CLI is the implementation carrier, not a treatment
of transport. Keep the old model results as motivation with their original method IDs.

Stop the tool block once all planned cases, independence checks, parity checks and hash
checks are recorded. The next agent experiment is a separate protocol: two fixed models,
matched Bound/Unbound facts and candidate order, full request/response/usage, task-level
paired first-grounding and strict completion. Do not reuse historical freezes or invent
LLM performance from this zero-model block.
