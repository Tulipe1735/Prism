# Selected evidence scope: prospective follow-up control

Date: 2026-10-05. This follow-up was designed after observing CLI contract v1, before
its own execution. It is post-hoc mechanism follow-up, not part of the original frozen
primary block. Zero model calls; no policy-learning or recovery result.

Question: after seeing the same Relations observation, does selecting Local evidence
through the existing context command change validation and goal correctness? Four
ordinary DOM families, one state/skeleton each, two goals, three selected-evidence
policies, one group swap: 4 × 2 × 3 = 24 actual CLI cases. Always Relations, always
Local, or a fixed task-type rule (group goal → Relations; entity goal → Local). The
task-type rule uses the known experimental condition, not an LLM inference. No new
production flag or goal-aware validator is added.

Every policy sees Relations first; Local is requested before mutation. Freeze the
initially correct instrument choice, then change its group while preserving the node.
Use the chosen view's evidence ID for act. Score independent current app state and
actual click events. Report wrong input, valid input refusal, acknowledgement and oracle
attainment. No success label for refusal and no population inference.

Predictions: always Relations refuses a valid entity-goal action; always Local can allow
a wrong group-goal action despite the prior richer observation. The fixed rule avoids
both on this narrow group-swap intervention. Local-note updates, late races and missing
relations remain outside this rule's protection, as measured in the primary block.

This tests the interface's expressiveness and trust boundary: selected evidence is not
proof of which facts a model actually relied on. A controller that downgrades evidence
can underbind its action. It does not establish that an autonomous agent can infer
minimal dependencies. Save new source freeze, commands and raw records separately.
