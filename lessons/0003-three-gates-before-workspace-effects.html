Prism / Lesson 0003 / 约 10 分钟

一个路径合法，为什么仍然不能读？

这节课只练一个能力：拿到 workspace 请求后，判断它会在哪一道门被拒绝。 学完后，你应能区分 Schema、policy 与真实文件系统，并解释 为什么 timeout 结束后还必须等待 process tree 清理。

01 / Gate one

Schema 只证明“能讨论”，不证明“已授权”。

{
  operation: "test",
  command: { executable: "pnpm", arguments: ["test"] },
  workingDirectory: ".",
  timeoutMs: 120000
}

workspaceRequestSchema 会拒绝 ../outside、绝对路径、带换行的 argument，以及把 pnpm test && ... 塞进 executable 的 shell 形状。但通过 schema 只说明它是一个可验证的 typed proposal；它还没有获得执行权。

02 / Gate two

Policy 比较完整 argv，不比较“看起来差不多”。

Registered

pnpm
["test"]
cwd: "."

Denied

pnpm
["test", "--update"]
cwd: "apps/web"

executable 相同不够。sameCommand 要求参数数量与每个位置都相等，working directory 也必须独立命中注册表。 Execa 收到的是 executable + arguments[]，并设置 shell: false； 因此运行时 prose 不能靠 quoting 或 shell operator 扩张能力。

03 / Gate three

字符串在 root 内，symlink 的真实落点也可能在 root 外。

  1. PARSErelative path
  2. RESOLVEworkspace root
  3. POLICYallowlist / ignore
  4. REALPATHfollow actual target
  5. BOUNDredact + capture

linked/secret.txt 在字面上位于 workspace；若 linked 是指向外部目录的 junction/symlink，realpath 会暴露真实目标，executor 返回 symlink_escape。发现文件时 fast-glob 本身也使用 followSymbolicLinks: false；root 与 nested .gitignore 再由 ignore 按目录层级过滤。

04 / Runaway work

timeout 不是一个状态字；它是一个清理承诺。

Node 官方文档明确提醒：杀掉 parent 不保证杀掉 descendant。Prism 在 POSIX 为命令建立独立 process group，对 group 发送 TERM/KILL；Windows 使用 taskkill /t /f。只有清理 promise 完成以后，evidence 才能返回 timed_out 或 cancelled。

真实测试让 grandchild 每 20 ms 写一次 heartbeat；executor 返回后再等待， 文件大小和 mtime 必须保持不变。测试观察的是公开承诺“没有遗留工作”， 不是某个私有 kill 函数被调用过。

05 / Durable evidence

拒绝也要能在刷新后解释。

executor 先截断并脱敏 stdout、stderr 与读取内容，再返回 WorkspaceEvidence。Run repository 将它序列化为 SHA-256 artifact， 追加 workspace.evidence 事件；刷新时 journal 重放回 dossier。 因此 GUI 显示的“为什么停下”不是临时 toast，而是可验真的 Run 事实。

WorkspaceExecutor → writeArtifact → workspace.evidence → projectRunEvents → RunDossierView
06 / Retrieval

不看源码，给三个请求分流。

A：../package.json。B：合法的 node ["-e", "..."]，但注册表 只有 pnpm ["test"]。C：allowlisted 的 linked/secret.txt，而 linked 指向 workspace 外。分别在哪一道门失败？

A 在 contract gate：path_escape。B 通过 contract、在 policy gate： command_not_allowlisted。C 通过字符串与 allowlist 检查、在 reality gate：symlink_escape。
