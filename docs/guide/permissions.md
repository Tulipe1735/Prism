# 权限范围与审批：实现说明

本文件说明权限范围与审批的实现边界；对外契约见[内核接口](../reference/kernel.md)。

## 两个正交概念

- **权限范围（Permission Scope）**：`read-only` | `workspace-write`（默认）|
  `full-access`，决定文件效果与命令的边界。
- **审批（Approval）**：越界动作发生前，由用户逐次决定是否执行；只生效一次，不记忆。

内核只做「工具执行前判定」，不做 OS 级沙箱。工具声明它会做什么（`Tool.effects`），内核用
`PermissionPolicy`（`src/kernel/permissions.ts`）逐项判定，判定通过才调用
`Tool.execute`。因此拒绝的动作**从未发生**，不会留下半成品效果。

## 判定表

| 动作           | `read-only` | `workspace-write` | `full-access` |
| -------------- | ----------- | ----------------- | ------------- |
| 读文件         | 允许        | 允许              | 允许          |
| 写工作区内文件 | 拒绝        | 允许              | 允许          |
| 写工作区外文件 | 拒绝        | 审批              | 允许          |
| 命令           | 拒绝        | 允许              | 允许          |
| 浏览器动作     | 允许\*      | 允许\*            | 允许\*        |

\* 浏览器动作不受范围约束（范围只管文件效果），只受「需审批」开关约束。

三点取舍：

1. **只读档拒绝而不是请求审批。**
   只读是用户设的硬上限：内核直接拒绝，并把「换一种做法或如实汇报，不要重试」写进工具结果。要写入时由用户切换档位，不由模型逐次请求放宽边界。
2. **读永远允许。** 探索仓库需要读工作区外的文件（例如全局
   `AGENTS.md`）。范围按写效果与命令实施。
3. **命令不逐条审批。**
   命令可能产生的文件效果无法在判定阶段看清；因此命令随档位自动：只读拒绝，工作区可写与完全访问直接执行。需要更细的边界时用只读档。

## 审批协议

- 需要在工具调用**内部**发起时，工具调用
  `context.requestApproval(request)`（内核提供）。内核把请求登记为待审批、发
  `approval.requested`（含 `tool`、`reason`、`target`、 `impact`），用户经
  `POST /sessions/:id/approvals/:requestId` 应答一次。
- 重复应答、未知 id、已失效的请求都返回 404 `APPROVAL_NOT_FOUND`。
- 内核不缓存批准：同一次调用里重复的动作只请求一次（按动作去重）；下一次调用即使参数完全相同也要重新请求。
- 取消运行中的任务时，该会话的待审批按「拒绝」处理，动作不执行。
- 模型读到拒绝的方式与其它工具失败一致：`tool_result.isError` 为
  `true`，正文说明原因并提示不要重试。

## 浏览器动作的「需审批」开关

- 配置项：`config.json` 的 `browser.actionsNeedApproval`（默认 `false`）。
- 修改：`PUT /settings` 的 `{ "browser": { "actionsNeedApproval": true } }`。
- 判定接口：`PermissionPolicy.decide({ kind: "browser-action", action, target }, workspace)`
  返回 `allow` 或 `approval`；浏览器工具声明该动作即可，无需自己判断开关。
- 开关与档位正交：`full-access` 下打开开关，浏览器动作同样逐个审批。

## MCP 工具不纳入三档范围

MCP 工具不声明 `effects`，内核不做范围判定，也不发审批请求。

理由：三档范围按文件路径与命令实施，而 MCP 服务器在外部进程里做事，其效果（网络、远端系统、它自己的凭据）无法从工具参数推断。为它们编造一个假的「文件边界」会让用户误以为边界已生效。因此 v1 明确：三档范围只覆盖内核自带的文件与命令工具；MCP 服务器的接入由用户在配置里自行选择，其能力边界由 MCP 服务器本身负责。将来若需要，再给 MCP 工具加「总是审批」这一档，而不是复用文件范围。

## 已知限制

- 路径按解析后的字符串比较，**不跟随符号链接**：工作区内指向外部的符号链接可以绕过范围判定；工作区外经符号链接指向内部的路径会被误判为越界（偏安全的一侧）。
- 没有 OS 级沙箱：命令一旦获准，它自身的文件效果不受范围限制。
- 判定只看声明的动作。工具漏声明效果就等于没有边界，因此新增会写文件、跑命令、驱动浏览器的工具时必须声明
  `Tool.effects`（见内核接口的工具一节）。

## Creator Mode

Creator
Mode 的安装、更新、启停、重载和移除动作按命令权限处理，只读范围拒绝模型发起的修改。查看插件与读取开发契约不产生写效果。用户可在右侧插件栏中启停和移除插件。插件在内核进程中执行可信代码；它必须正确声明工具效果，权限范围不隔离插件代码本身。
